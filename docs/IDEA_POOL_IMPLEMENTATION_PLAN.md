# 创业话题灵感池：实现落地方案（Pyramid）

## 1. 顶层目标（Why）

构建一个“可持续产出高质量创业话题”的灵感池系统，满足三件事：

1. **覆盖广**：跨行业、跨人群、跨中英文信息源。
2. **质量高**：可验证痛点、可落地、可变现、与既有项目不重复。
3. **可执行**：每周稳定产出可直接进入辩论引擎的候选话题。

---

## 2. 第一层拆解（What）— 四大能力域

### A. 多源信号采集（Signal Ingestion）
- 目标：拿到“用户真实痛点 + 技术前沿 + 商业验证 + 政策窗口”四类信号。

### B. 结构化评估与去重（Signal Intelligence）
- 目标：把原始噪声转化为可排序候选，并严格去重。

### C. 创意碰撞与定向生成（Idea Generation）
- 目标：不是只“抓热点”，而是产出“新解法话题”。

### D. 人机协同闭环（Ops Loop）
- 目标：可配置、可审计、可持续优化命中率。

---

## 3. Gemini 思路分析（你给的图）

## 3.1 优点（可直接采用）
- **A. 趋势与痛点捕获**：方向正确，尤其“底层痛点”是高价值入口。
- **B. 技术与商业前沿**：能避免仅做“用户吐槽收集器”，引入技术供给侧。
- **C. 结构化碰撞**：能从“信息汇总”升级到“方向创造”。

## 3.2 缺口（需要补强）
- 缺少**统一评分框架**（痛点强度/可落地/可变现/新颖度）。
- 缺少**跨源语义去重机制**（同义话题反复出现）。
- 缺少**可执行约束**（个人开发者是否能在低成本下启动）。
- 缺少**质量闭环指标**（被选中话题后续辩论通过率、转化率）。

---

## 4. 在 Gemini 基础上的补充（新增信号源）

为提高“可落地创业价值”，建议新增 5 类来源：

1. **招聘需求信号**（Boss/拉勾/LinkedIn 岗位趋势）  
   - 看企业正在为哪些能力付费，验证真实需求。
2. **开源与开发者需求信号**（GitHub Trending、Issue 热词）  
   - 看开发者在“造什么、缺什么、骂什么”。
3. **工具付费意愿信号**（Product Hunt/G2/应用商店评论）  
   - 看用户愿意为何类工具持续付费。
4. **采购与政策预算信号**（政府公告、招投标、行业专项）  
   - 看“钱在哪儿”，尤其 ToB/ToG 场景。
5. **行业运营实务信号**（SOP、灰度流程、数据流程痛点）  
   - 从“业务流程低效”切入，减少纯概念化话题。

---

## 5. 第二层拆解（How）— 方案架构

## 5.1 数据流总览
`采集插件 -> 原始话题 -> 语义归一化 -> 打分排序 -> 创意重写 -> 人审/自动入辩论`

## 5.2 与现有项目的映射（当前已具备）
- 已有插件：
  - `52pojie`
  - `keyword_search`（Bing/百度）
  - `trend_search`（中英趋势词）
  - `llm_creative`（创意生成）
- 已有流程：
  - 去重保存、AI 精选、自动提交辩论、后台可配置。

## 5.3 需要新增的插件（建议）
- `social_pain`：小红书/Reddit/知乎痛点帖子抓取。
- `academic_frontier`：arXiv/HuggingFace Trending。
- `funding_signal`：36氪/TechCrunch/Crunchbase 融资动态。
- `policy_signal`：政策公告、专项资金、行业监管更新。
- `demand_signal`：招聘/采购/评论中的付费需求信号。

---

## 6. 评估模型（统一打分）

对每个候选话题计算总分（0-10）：

`总分 = 0.30痛点强度 + 0.20趋势增速 + 0.20落地可行 + 0.20变现清晰 + 0.10新颖度`

字段解释：
- **痛点强度**：负面情绪密度、重复抱怨频次、任务刚需程度。
- **趋势增速**：近 7/30 天热度增长率。
- **落地可行**：是否适配“小团队/低成本/短周期验证”。
- **变现清晰**：付费主体明确、客单价路径明确。
- **新颖度**：与现有 ideas 与近期候选的语义距离。

准入门槛建议：
- 总分 `>= 7.0` 才进入“推荐”。
- 总分 `>= 8.0` 才进入“自动提交辩论候选”。

---

## 7. 去重策略（必须项）

双层去重：

1. **快速去重**：标题规范化 + hash（现有机制保留）。
2. **语义去重**：向量相似度 + LLM 判重（新增硬阈值）。

规则建议：
- 与历史 `ideas` 相似度 `> 0.85`：直接过滤。
- 相似度 `0.75~0.85`：进入人工复核队列。
- 相似度 `< 0.75`：保留。

---

## 8. 运营闭环（管理后台）

新增/强化后台能力：
- 信号源开关、抓取频率、预算上限。
- 每个来源命中率（被选中率、辩论通过率）。
- 话题生命周期状态：`raw -> scored -> shortlisted -> debating -> archived`。
- 可解释推荐：每个话题显示“入选理由 + 分项分数 + 证据来源”。

---

## 9. 分阶段实施（执行计划）

## Phase 1（1-2 周）：稳态可用
- 接入 `social_pain`、`academic_frontier`、`funding_signal` 三个插件。
- 上线统一评分模型（先规则版）。
- 增加语义去重阈值。

验收：
- 每天新增候选 >= 50
- 重复率下降 >= 40%
- 推荐话题人工认可率 >= 60%

## Phase 2（2-4 周）：质量提升
- 接入 `policy_signal`、`demand_signal`。
- 打分升级为“规则 + LLM 解释”混合模型。
- 后台加上来源命中率看板。

验收：
- 推荐话题进入辩论后“promising+graduated”占比 >= 35%

## Phase 3（持续）：闭环优化
- 引入“辩论结果反哺”训练打分权重。
- 按行业构建专题灵感池（如 AI+医疗、AI+教育、AI+本地生活）。
